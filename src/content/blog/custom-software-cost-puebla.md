The price of a custom system depends on the problem it needs to solve. An application that collects requests has a different scope from a platform with multiple modules, user roles, and integrations.

In Puebla, a **custom web app can start at $15,000 MXN**. For an internal system that centralizes information and automates processes, the starting price is **$20,000 MXN**. These are starting points: the final quote comes after reviewing the workflow and agreeing on scope.

## What affects the cost

### 1. The workflow and its rules

First, we need to understand what information comes in, who reviews it, what decisions are made, and what outcome the team needs. A simple form has a different scope from a process with approvals, exceptions, and several people responsible for different steps.

### 2. The modules you need

A system can start with one specific function and grow later. For example, a first version might record requests; a later stage could add a dashboard, notifications, or follow-up. Defining what is essential for the first version helps prioritize the budget.

### 3. Users and permissions

When people or departments need different access to information, the system needs roles and permissions. User count alone does not determine the price, but access rules and responsibilities are part of the project scope.

### 4. Integrations and reports

Connecting external services, importing existing data, or generating reports adds analysis and testing work. It is best to include integrations that solve a real need in the workflow.

## How to define a first version

Before development, it helps to answer these questions:

- Which repetitive task or problem should be addressed first?
- Who enters the information and who needs to review it?
- Which data must be recorded?
- What should the team be able to see at the end?
- What can wait for a later phase?

Those answers help describe a first version, agree on modules, and estimate the work with less uncertainty. The process can include discovery, design, prototyping, development, testing with representative data, and implementation.

## When does custom software make sense?

It may be worth exploring when an important process depends on duplicate files, repeated data entry, or reports someone combines manually. If a spreadsheet handles a simple task well, it does not need to be replaced just for the sake of using software.

The goal is not to build the largest platform. It is to address the first bottleneck with a scope the team can adopt.
